# 뉴스 데이터 형식 (초안 v0.1)

프론트가 화면을 그리는 데 쓰는 데이터 형식입니다. 백엔드(조서연)가 이 형식대로 JSON을 주면 화면이 그대로 동작합니다.
실제 예시는 `src/data/mock-news.json`에 있습니다 (모두 지어낸 내용).

> 초안입니다. 서연님과 논의해서 바꿔도 됩니다. 특히 아래 "논의할 점"을 확인해 주세요.

## 전체 구조

```json
{
  "meta": { "note": "설명", "version": "0.1", "generatedAt": "2026-11-03" },
  "sourceTypes": [ ... ],
  "outlets": [ ... ],
  "issues": [ ... ],
  "articles": [ ... ]
}
```

## sourceTypes — 인용 출처 유형

| 필드 | 뜻 | 예 |
| --- | --- | --- |
| `id` | 유형 코드 | `"gov"` |
| `label` | 화면에 보이는 이름 | `"정부·여당"` |

- 지금은 임시로 4개(정부·여당 / 야당 / 전문가 / 시민)입니다. **유형을 몇 개로 나눌지는 아직 정하지 않았습니다.**
- 이 목록만 바꾸면 화면의 막대그래프·범례·비교 문구가 자동으로 바뀝니다.

## outlets — 언론사

| 필드 | 뜻 | 예 |
| --- | --- | --- |
| `id` | 언론사 코드 | `"garam"` |
| `name` | 언론사 이름 | `"가람일보"` |

## issues — 이슈 (같은 사건을 다룬 기사 묶음)

| 필드 | 뜻 | 예 |
| --- | --- | --- |
| `id` | 이슈 코드 | `"issue-001"` |
| `title` | 이슈 제목 | `"가상시 청년 월세 지원 확대안"` |
| `summary` | 한두 문장 요약 | |
| `category` | 분야 | `"사회"` |
| `date` | 날짜 (YYYY-MM-DD) | `"2026-11-03"` |
| `articleIds` | 이 이슈에 묶인 기사 id 목록 | `["art-001", "art-002"]` |

## articles — 기사

| 필드 | 뜻 | 누가 만드나 |
| --- | --- | --- |
| `id` | 기사 코드 | 수집 |
| `issueId` | 속한 이슈 id | AI (이슈 묶기) |
| `outletId` | 언론사 id | 수집 |
| `title`, `summary` | 제목, 짧은 요약 (본문은 싣지 않음) | 수집 |
| `url` | 원문 링크 | 수집 |
| `publishedAt` | 발행 시각 (ISO 8601) | 수집 |
| `sentences` | 문장별 분석 결과 (아래) | AI |
| `framingTerms` | 사건을 특정하게 표현한 단어 | AI |
| `missingViewpoints` | 이 기사에서 빠진 관점 | AI |

### sentences — 문장별 분석

```json
{ "id": "s2", "text": "시 관계자는 \"...\"이라고 말했다.", "type": "fact", "sourceType": "gov", "sourceName": "시 관계자" }
```

| 필드 | 뜻 | 값 |
| --- | --- | --- |
| `id` | 문장 코드 (기사 안에서만 겹치지 않으면 됨) | `"s1"` |
| `text` | 문장 | 분석에 쓴 문장. 저작권 때문에 화면에 전부 보일지는 논의 필요 |
| `type` | 사실/의견 | `"fact"` 또는 `"opinion"` |
| `sourceType` | 인용 출처 유형 id | `"gov"` 등, 인용이 없으면 `null` |
| `sourceName` | 인용한 사람·기관 | `"시 관계자"`, 없으면 `null` |

### framingTerms — 프레이밍 어휘

```json
{ "term": "돌려막기", "sentenceId": "s2" }
```

`term`은 그 문장 안에 **똑같은 글자로** 들어 있어야 화면에서 강조됩니다.

### missingViewpoints — 빠진 관점

```json
{ "sourceType": "opp", "description": "재원 마련 방식에 대한 야당의 문제 제기가 없음", "foundInArticleIds": ["art-002", "art-004"] }
```

| 필드 | 뜻 |
| --- | --- |
| `sourceType` | 빠진 관점의 출처 유형 |
| `description` | 화면에 보일 설명 한 문장 |
| `foundInArticleIds` | 같은 이슈에서 이 관점이 담긴 기사 id |

## 프론트가 직접 계산하는 것 (백엔드가 안 줘도 됨)

`src/lib/news.js`에서 위 데이터로 계산합니다.

- 기사별 인용 출처 비중: 출처가 있는 문장 중 유형별 비율
- 이슈 평균 인용 출처 비중
- 의견 문장 비율
- "같은 이슈의 다른 기사와 비교" 문구 (차이 20%p 이상, 또는 다른 기사에는 있는데 이 기사에는 없는 유형)
- 다른 시각의 기사 추천 (인용 출처 비중이 가장 다른 기사 순)

## 논의할 점 (서연님과)

1. 인용 출처 유형을 몇 개로 나눌지 (지금 임시 4개)
2. 비율 계산을 프론트에서 할지, 백엔드가 계산해서 줄지 (지금은 프론트 계산)
3. 문장 `text`를 화면에 전부 보여도 되는지 (저작권) — 안 되면 근거 문장만 일부 보여 주는 방식으로 변경
4. 데이터를 JSON 파일 하나로 줄지, API 주소로 줄지

## 읽은 기록 저장 (백엔드가 만들 기능 — 제안)

지금은 `src/lib/reading-history.js`가 브라우저(localStorage)에 저장합니다. 데이터베이스에 저장하려면 백엔드에 아래 두 기능이 필요합니다. 프론트는 이 파일만 바꾸면 됩니다.

| 기능 | 요청 | 내용 |
| --- | --- | --- |
| 기록 저장 | `POST /reading-history` | `{ "userId": "...", "articleId": "art-003", "kind": "view", "readAt": "2026-11-03T14:18:01Z" }` |
| 내 기록 불러오기 | `GET /reading-history?userId=...` | 위 기록들의 배열 (최신순) |

- `kind`: `"view"` = 우리 사이트에서 기사 분석 화면을 연 것, `"original"` = "원문 보기"를 눌러 언론사 기사로 이동한 것. 어느 쪽을 '읽음'으로 칠지는 아직 결정 전이라 둘 다 기록합니다.
- `userId`: 사용자 구분 방식(로그인 / 익명 아이디)이 정해지면 확정합니다.
- 편향 계산과 다른 관점 추천은 프론트가 이 기록으로 계산하므로 백엔드는 저장·불러오기만 하면 됩니다.

## 기사 원문 주소

- `articles[].url`에 언론사 원문 주소를 넣어 주세요. 화면의 "○○에서 원문 보기 ↗"가 새 탭으로 열립니다.
- 지금 예시 데이터는 지어낸 기사라 `"#"`이고, 화면에는 "원문 링크 준비 중"으로 보입니다.

## 11/3 결정 (남지원)

- 분석 화면(기사 상세)에는 **기사 문장을 보여 주지 않습니다.** 보여 주는 것: 제목, 요약, 인용 출처 비교, 이 기사에 없는 인용, 평가가 담긴 표현(단어만), 인용한 사람, 다른 시각의 기사. 문장은 원문 링크에서 확인합니다.
  - 그래도 문장별 분석(`sentences`)은 백엔드에서 계속 보내 주세요. 비율 계산과 인용한 사람 목록에 씁니다.
- **'읽은 기사' = '원문 보기'를 누른 기사**(`kind: "original"`). 내 읽기 편향은 이것만으로 계산합니다.
- **분석 화면을 연 기사(`kind: "view"`) = 그 이슈에 관심이 있음.** 내 읽기 편향 화면의 '관심 있는 주제'에 씁니다.

## 11/4 결정 (남지원)

- 사실/의견은 **비율 + 의견 문장 짧은 인용**으로 보여 줍니다. 기사당 의견 문장 최대 2개, 앞 40자까지만, 언론사명 표시. (개수·길이는 `src/app/articles/[id]/page.js`의 `QUOTE_MAX`, `slice(0, 2)`에서 조정)
- 결정 사항: A1, C1+C2, D3, E1, F1, G3. B, D3의 점수 기준, G3의 인용 출처 유형은 서연님과 논의 예정.
- 이슈에 `category`(사회 / 경제 / 생활 …)를 꼭 넣어 주세요. 첫 화면에서 분야별로 골라 보는 데 씁니다. (G3)
- 내 읽기 편향 화면 맨 위에 **이번 주 리포트**(최근 7일, C2)가 있습니다. 기록의 `readAt`(읽은 시각)으로 계산하니, 백엔드로 옮겨도 `readAt`은 꼭 같이 저장해 주세요.

## 11/5 결정 (남지원·조서연)

- 인용 출처 유형 **5개**: `gov` 정부·여당 / `opp` 야당 / `expert` 전문가 / `citizen` 시민·단체 / `industry` 기업·업계
- 모든 그래프(기사, 이슈 평균, 내 읽기 편향)는 **비중이 큰 상위 4개**만 그 유형 색으로 그리고, 나머지는 **'기타'(연회색)** 로 묶습니다. 비중이 같으면 위 유형 순서가 앞인 것을 남깁니다. (`src/lib/news.js`의 `chartEntries`, `TOP_N`)
- 백엔드는 사실 문장의 `text`를 빼고, 의견 문장만 40자로 잘라 보냅니다(서연님 제안). 잘린 문장은 끝에 '…'를 붙여 주세요. 프론트는 라벨(`type`, `sourceType`, `sourceName`)로 계산하므로 그대로 동작합니다.
